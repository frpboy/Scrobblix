# Definition of Ready

An implementation issue is ready only when it has:

- a concrete user/system outcome;
- scope and explicit non-scope;
- linked requirement, use case, or defect evidence;
- acceptance criteria that can be tested;
- relevant architecture/data/security/privacy implications;
- UI states and accessible behavior when user-facing;
- migration/compatibility implications when persistent contracts change;
- dependencies and blocked-by relationships;
- an owner or clear contribution status;
- no unresolved question that can materially change the implementation.

Exploration/spike issues may be ready with a time-bounded question, evidence to collect, and decision artifact to produce rather than product acceptance criteria.
