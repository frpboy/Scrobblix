# Windows media session collector qualification

A user recording shows Windows media controls exposing a playing Mornye track while Scrobblix Sources remains unobserved. Subsequent private logs and a startup banner identified a storage initialization abort before tracking, with a migration checksum mismatch. The video is not proof of a GetCurrentSession defect or missing Last.fm credentials. Local collection starts independently of Last.fm setup. The separate bounded LF/CRLF compatibility fix shipped in beta5; its success on the reported PC remains unverified. No private logs, settings or listening data are published or reset.

This branch adds a bounded synthetic native Windows MediaPlayer session test. It creates a muted silent local PCM file, explicitly publishes synthetic SMTC title/artist and Playing/Paused state, and requires the actual GsmTcPlaybackObservationSource to observe those values. No user files, accounts, network or database are involved. Local cross-target compile and actual Windows execution pass at6d34538 (run42361844227), including title/artist and Playing/Paused assertions. Paused assertions require the fixture identity, existing pipe/credential checks run first, and file-cleanup failure does not mask assertions. Updated base heads require fresh CI. A passing synthetic test qualifies this controlled session only, not Mornye, every player or the reported PC. A failed hosted Windows test must be diagnosed as either product behavior or fixture/platform limitation before drawing a user-device conclusion. No production collector fix is guessed from the recording.
